# 首页 tint 图标牌 + 卡片白面 · 设计说明

> 原型：[`design/home-tint-chips/index.html`](../../../design/home-tint-chips/index.html)
> 落地：**1.4.62**（图标牌 + 白面浮起 + 分割线换色）
> 后续：**1.4.63** 把 `ActivityItem` 与常用仓库管理页的灰底行接到同一套（单独一个提交）

## 一、怎么打开

`design/home-tint-chips/index.html` 直接双击，或在 DSH 侧边栏「原型预览」打开。工具条三组开关：

| 开关 | 作用 |
|---|---|
| 浅色屏 | 左屏内容切「改造后 / 现状」，用来对照图标那一格 |
| 配色 | 语义三色 / 单色系（靛蓝） |
| 卡片 | 灰底 / 描边 / 浮起 / 无卡 |

左右两屏**固定**为浅色与深色 —— 主题并排才比得出来「浮起在深色下等于不存在」。

## 二、结论（2026-11-27 拍板）

1. **图标 = 语义三色**：区块标题的图标统一成 `TintChip`（22dp 牌 / 7dp 圆角 / 13dp 图标 /
   同色 12% 底），颜色按「去哪」分配：待处理 = `WARNING` 橙、常用仓库 = `DONE` 紫、
   最近活动 = `ACCENT` 蓝。单色系变体没采用：颜色承担「用途编码」，退成层级标记反而丢信息。
2. **卡片 = 白面 + 4dp 阴影**（圆角 12dp）。深色下阴影不可见，由 `canvasSubtle`（`#161B22`）
   与 canvas（`#0D1117`）的明度差承担分组。
3. **灰底下线**。三条理由见 §四。
4. **卡内分割线从 `BorderEmphasis × 40%` 换成 `Primer.Border`**。理由见 §五。

## 三、规格

| 项 | 值 | 说明 |
|---|---|---|
| 牌 | 22 × 22dp | 圆角 7dp（≈ 0.27） |
| 牌内图标 | 13dp | ≈ 0.59；换尺寸时三个一起换 |
| 牌底色 | 图标色 × **12%** | alpha 合成，换卡片面自动跟着变 |
| 牌 ↔ 标签 | 8dp | 裸图标时代是 6dp，牌高 4dp 后要补 |
| 卡片面 | `Primer.BackgroundSecondary` | 浅色 `#FFFFFF` / 深色 `#161B22` |
| 卡片阴影 | 4dp | 原型是双层柔光，Compose 只有一个 elevation |
| 卡片圆角 | 12dp | 原 10dp；有阴影后大一号才不显得薄 |
| 卡内分割线 | `Primer.Border` | 浅 `#BFC1C9` / 深 `#30363D` |

## 四、为什么灰底（`Gray100`）下线

1. **浅色下它是「一块被染灰的白」**。灰底与白底只差 5% 明度，分组靠这点差硬造；
   而同一屏里正文、链接、图标的对比都远高于它 —— 分组标记成了最不值得看的东西。
2. **深色下它等于没换**。`Gray100`（`#161B22`）正好是深色板的 `canvasSubtle`，
   和「白面卡片」在深色下是**同一个面**：浅色的问题是浅色独有的，深色本来就已经是浮起的样子。
3. **白面 + 阴影一份代码覆盖两套主题**：浅色靠阴影分层，深色靠明度差分层，
   不需要给卡片写主题分支。

## 五、为什么分割线要换色（真机反馈）

1.4.62 第一版装机后，用户反馈「浅色待处理展开的分割线有点抢眼」。

根因：`TodoDivider()` 用的是 `BorderEmphasis × 40%`，而 `BorderEmphasis` 在浅色板里是**纯黑**。
40% 纯黑压在原本的灰底上刚好；卡片换成白面之后，**同一根线成了整页对比度最高的元素** ——
第一眼看到的是线，不是「待处理」三个字。换成描边色后线还在，但退回「分组」该有的重量。

副作用（已知并接受）：深色下这根线也从 `#30363D × 40%` 变成全量 `#30363D`，比之前略明显，
但对比度仍低（约 1.3:1）。

## 七、未落地与边界

- **`ActivityItem`**（28dp 白圆 + 黑色图标）与**常用仓库管理页**的灰底行：1.4.63 单独提交；
- **仓库页 / 个人页的卡片**仍是上一代（各自容器语言不同），没有跟着改 —— 首页这次只收「首页 + 管理页」；
- **深色 12% 是否提到 15%**：原型里验证过「深色 12% 偏闷」，但拍板保留 12%（GitHub Primer 深色用的
  是 15%）。要改是一行常量的事，留给后续单独评估；
- 牌尺寸与字重没有做响应式：22dp 是常态，紧凑屏/大字号下的降级未验证。
