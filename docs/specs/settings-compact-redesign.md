## 一、决策原文（2026-11-26，用户）

1. **单一入口条目**，不带多余任何描述；
2. 入口条目**匹配图标**；
3. 入口条目描述精简；账户分类转成「图标 + 账号管理」，点击进入完整管理页，**不显示当前登录账户**；
   其他同类照办；
4. 条目入口复用 `c77e8fc`（常用仓库卡压密 + 可见底色）的代码，**整体比例压密**；
5. 其他页面的重构**排单**：压前/压后、可交互记录、是否优化、更改方案选择组合（+ 文档，交接用）；
   **当前只重构设置长页面，不涉及其他页面**；
6. 交互文件要能**从侧边栏直接打开**操作与可视化，**一份文件、不起服务**。

## 三、实现：密度是「外参」，不是第二套行组件

`SettingsRow.kt` 新增 `SettingsDensity`（`Comfort` / `Compact`）+ `LocalSettingsDensity`
（`staticCompositionLocalOf`，默认 `Comfort`）。**行型仍是那六种**，`SettingsScreen` 在根部
`CompositionLocalProvider(LocalSettingsDensity provides SettingsDensity.Compact)`。

为什么不写一套 `CompactNavRow`：设置树已经吃过「同一件事 8 套组件」的亏（`SettingsRow.kt` 文件头）。
再来一套「紧凑行型」，等于把刚收掉的 8 套换成 2 套 × 6 种 —— 二级页迁过来时又要二选一。

| 指标 | Comfort（二级页） | Compact（主页） |
|---|---|---|
| 行最小高度 | 48dp | **44dp** |
| 左右内边距 | 16dp | **14dp** |
| 行首图标 | 20dp | **18dp** |
| 图标↔文字 | 12dp | 10dp |
| 文字↔值 / 尾控件 | 10dp | 8dp |
| 分组上下留白 | 6dp | **4dp** |
| 组标签 | 12sp / 下 6dp | 11sp / 下 4dp |
| 名称垂直内边距 | 11dp | 9dp |
| 说明（若用） | 12sp / 17sp 行高 | 11sp / 15sp |
| 值列字号 | 12sp | 11sp |
| `›` | 20dp | 18dp |
| 卡片底 | `BackgroundSecondary` | **`Gray100`**（两档统一，不再分档） |
| 卡片描边 | `BorderEmphasis`（浅色 = 纯黑 1dp） | **无** |
| 行分隔线 | `BorderEmphasis` 实色 | **`BorderEmphasis` @ 40%**（同首页 `TodoDivider`） |
| 卡片圆角 | 10dp | 10dp（与首页 `HomeGroupCard` 同一套容器语言） |

**为什么卡片底要换**：浅色板里 `BackgroundSecondary == 画布纯白`。旧主页靠行内说明把行撑高，
「缝」靠文字节奏读出来；说明一删，卡片内留白与卡片间间距就并成一片白 —— 压缩只会看着更糊。
这条结论与 c77e8fc（常用仓库卡）完全一致：**先给边界，再谈压密**。

**为什么边界不能是黑线**：第一版压密保留了 `BorderEmphasis`（浅色 `#000000`）的 1dp 卡片描边，
真机截图里七张卡 + 行分隔线 + 分段控件一起变成一张线框图 —— 用户反馈「取消掉黑边」。
现在卡片不描边、分隔线降到 40%，边界只由 `Gray100` 底与 10dp 圆角给；这与首页
`HomeGroupCard`（浅灰底、无描边）以及 1.4.37「更多手柄去黑边」是同一条结论：
**纯黑线是最后手段，不是默认装饰**。交互控件（分段控件 / 二级按钮）的边界仍走 `BorderControl`，
那是 WCAG 1.4.11 要求的 3:1，不属于装饰。

## 四、账户：为什么删掉「我是谁」

- 旧账户卡回答的是「当前登录是谁 + 状态」（头像 / 登录名 / host / 胶囊），但主页**回答不了**
  「怎么换、还有谁、这个令牌还行不行」——这些都在账号管理页（列表 + `⋮` + 删除确认）。
- 用户决策明确要求不显示当前登录账户；删掉之后，**账户组只剩一行入口**，图标 `Person` 与「账号管理」同义。
- 代价（已接受）：令牌失效/限流的状态不再在第一屏可见 —— 进账号管理 page 才看得到。
  若将来要恢复「异常才提示」，正确做法是在这一行挂**状态胶囊**（异常时出现、正常时不显示），
  而不是把整张身份卡搬回来。
- `AccountRow` 组件随之删除（唯一调用点就是旧主页）。若账号管理页将来需要这张卡，
  它的实现可从 git 历史取回，或直接用 `AccountsScreen` 现有的卡片。

## 五、保留不动的约束（规范里带「必须」的）

| 约束 | 现状 |
|---|---|
| 行必须来自 `ui/settings/SettingsRow.kt`（§4.1） | 主页 5 种行型：`NavRow` / `SwitchRow` / `ChoiceRow` / `DangerRow` / `DisabledNavRow` |
| 行尾控件由 `SettingsRowShell` 唯一决定（§4.2） | 未变 |
| 主题必须三档 `ChoiceRow`，不许循环手势（§5.2） | 保留 |
| 通知是导航行 + 状态胶囊，**不是**开关（§4.3） | 保留 |
| 禁用行必须写原因 + 给出去开启的路（§6.3） | 本地仓库行保留（唯一的两行行） |
| 危险行动作只打开确认（§7.2） | 保留，含对象名与「不可撤销」 |
| 落盘键只在 `SettingsKeys.kt`（§8.1） | 未变 |
| 组名与行名不许重复（§3.2） | 修掉：「通知」组不再挂同名的组标签 |

**值列留着的理由**：「跟随系统 / 单次提交 / 未设置 / 3 条 / 已开启 / N 个错误」是**值**，
不是**说明**：它们让一屏能读完「现在是什么状态」，且不进二级页也能判断。
删的是解释性文字（为什么、影响什么、怎么用），不是状态。

**风险与边界**

1. **44dp < Material 推荐的 48dp**。但仍 ≥ WCAG 2.5.5 / iOS HIG 的 44pt；行内只有开关/分段/`›`
   三类命中目标，且整行可点。真机若出现误触，把 `Compact.rowMinHeight` 调回 46–48 即可（一处改）。
2. **200% 字号未验**：说明删掉后每行只有一行名称，放大字号只会把行撑高，不会出现「说明挤掉值列」。
3. 深色下 `Gray100`（`neutralFill`）与画布有层次差 —— 与首页常用仓库卡同值，已在该处验证过。
