# 帧率基线（页面重建）· 口径 / 取数 / 验收

> **一句话**：慢帧不靠感觉调。取数只走 App 自己的 `FrameWatch`（与 `framestats` 同源、Beta 默认开、
> 落盘可读），口径钉在 `ui/log/FrameWatch.kt` 的常量里，验收只用**同一台设备 + 同一轮场景 + 同一份 `compare` 输出**。
>
> 真源：`app/src/main/java/com/branchbase/ui/log/FrameWatch.kt`（口径）·
> `tools/perf/frame-baseline.py`（取数与聚合）· 动效形式见 [`ui-design.md`](ui-design.md) §3。

---

## 1. 为什么需要这份文档

「切页面卡一下」「切走再切回来不如第一次顺」这类问题**会反复出现**，而每次的现场都不一样
（目标页首帧组合、主线程被别的工作占住、绘制量太大）。没有固定口径时，改完只能得到
「感觉快了」——既不能证伪，也不能回归。

三条本来一定会踩的坑，先说清楚：

| 坑 | 具体表现 |
|---|---|
| 想用 `dumpsys gfxinfo framestats` | 设备守护直接拦（`未识别的 dumpsys 参数`）；`dumpsys SurfaceFlinger --latency`、`perfetto` 同样不在放行名单 |
| 就算取到了 | 只留最近 ~120 帧（90Hz 上约 1.3s），且 dump 本身跑在**被测进程主线程**——测一次自己造一根柱子 |
| 想用 `logcat` | App 的 `Logger` **只落文件**，不打 logcat（`Logger.ui/net/remote/local` 全部进 `LogManager`），所以 logcat 里没有帧数据 |

结论：**唯一的取数通道是 `FrameWatch` 的日志文件**，而它恰好是最合适的那个（见 §2）。

## 2. 取数通道（唯一）

| 项 | 值 |
|---|---|
| 落盘路径 | `Android/data/com.branchbase/files/logs/<北京时间日期>/branchbase.log` |
| 权限 | **只读即可**（策略允许读任何目录；`Android/data` 只读） |
| 读法 | `adb-shell cat <path>`（受保护的设备 shell：**单条命令**，不能带管道/重定向/变量） |
| 开关 | `BuildConfig.FRAME_WATCH_DEFAULT`：debug / perfBeta 默认**开**，release 默认关；用户可在「设置 → 关于与诊断 → 慢帧日志」覆盖 |
| 保留 | 只留当天（跨天轮转 + 删历史目录），**跨天对比要当天取走** |

`FrameWatch` 用的是 `Window.addOnFrameMetricsAvailableListener` —— 与 `framestats` **同源**（系统每帧下发），
但发生在应用自己进程里：窗口长度只受内存限制、不打扰被测量的那次交互，而且每条慢帧都带
「当时最近一条 UI 日志」当页面注脚，**归因不需要另维护一份「当前页面」状态**。

## 3. 口径（改 `FrameWatch.kt` 就要回来改这里）

| 项 | 值 | 说明 |
|---|---|---|
| 慢帧明细 | 单帧 ≥ **32ms** | 记一条完整分段；同类限流 400ms，但**更慢的帧不会被吃掉**（单调升级，最慢的一定留得下） |
| 每分钟小结 | 窗口 **60s** | 窗口内出现过慢帧才记；「超 16ms M/T 帧」= 这一分钟的超预算比例 |
| 预算 | **16ms** | 60Hz 的经典阈值 |
| 分段 8 栏 | 等待 / 输入 / 动画 / 布局 / 绘制 / 上传 / 下发 / 交换 | 与 `framestats` 列一一对应；带 `*` 的是这一帧**最大**的一段 |

⚠️ **阈值按 60Hz 写死**。本机（OnePlus PJD110）`settings get system peak_refresh_rate` = 60，口径正确；
换到 120Hz 设备要按刷新率折算（16 → 8.33ms），否则「超 16ms」会**系统性低估**。

**归因读法**（这是整份口径里最有用的一条）：

- `等待` 最大 → 帧**根本没开始画**，主线程被别的工作占住 → 查「谁占了主线程」，换动画形式没用；
- `绘制` / `动画` 最大 → 这一帧真的在画（重组 + 绘制）→ 查「画了多少东西」；
- `下发` 最大 → 命令下发尖峰（大图层 / 纹理上传）→ 查图层与图片解码。

## 4. 工具：`tools/perf/frame-baseline.py`

```
watch    跟读设备日志（人操作期间用，随时可停）→ 原始切片落盘
analyze  解析切片 → .md 报表 + .json 数据（--from/--to 按 HH:MM:SS 切窗）
run      capture + analyze 一步到位
compare  改前 / 改后对比两份 .json
```

标准场景（每组之间停约 1 秒；人操作即可，脚本不驱动 UI）：

| 组 | 动作 | 次数 | 量的是什么 |
|---|---|---|---|
| S1 | 底栏「首页」↔「消息」 | 5 个来回 | `TabSwitcher` 同级切换 + **页面重建** |
| S2 | 个人页「概览」↔「动态」 | 5 个来回 | 重建 + 目标页首屏取数 |
| S3 | 仓库页「项目页」↔「代码」 | 5 个来回 | 重建 + 重内容页（列表 / WebView） |
| S4 | 首页 → 仓库详情 → 返回 | 3 次 | `PageSwitcher` 推进 / 返回（有方向位移） |
| S5 | 个人页 → More → 设置 → 返回 | 3 次 | 子页推进 + 设置页首帧 |

场景分类（脚本里的 `SCENARIO_RULES`）按**代码事实**归桶，不是按文案猜：

- `切换到「…」` 与 `进入消息页` → **Tab 同级切换（含重建）**：后者是 `NotificationScreen` 的打点，
  而它渲染在 `MainScreen` 的 `TabSwitcher`（`main-tab`）里 —— 底栏切 Tab 是同级切换 + 页面重建；
- `进入个人主页` / `进入设置页` / `返回` → **层级推进 / 返回**：走 `MainRoute.Profile`（depth=1）与设置子页。

产物：`tools/perf/reports/`（原始切片 + 生成的 `.md`/`.json`）**不入库** —— 那是「某一次采集」的数据；
结论回到本文档。

## 5. 基线（v1.0.53 · 2026-09-22 · 一轮场景）

| 指标 | 值 |
|---|---|
| 慢帧条数（≥32ms） | **27** |
| 最慢一帧 | **244.0 ms** |
| 慢帧均值 | 67.7 ms |
| 32–49ms / 50–99ms / ≥100ms | 12 / 10 / **5** |

| 主段 | 出现次数 | 该段均值 | 该段最大 |

## 6. 归因结论（三类，处置完全不同）

| 类型 | 判据 | 基线里的现场 | 该往哪下手 |
|---|---|---|---|
| **等待型** | `等待` 最大 | 「进入消息页」26.8–45.7ms；App 启动首帧 97.4ms | 主线程被占（cache-first 读、JSON、DB、类加载）。**换动画形式对这一类无效** —— 要么把活挪去后台，要么让动画**等目标页首帧就绪再起播** |
| **动画型** | `动画` 最大 | 仓库详情 244.0ms（动画 181.8）；「动态」142.3ms（绘制 70.4 + 动画 51.5） | 一帧里做完了整段推进动画的重组。对症的是**单页在屏**的过渡（fade-through / 快照图层）与**重叠期缩短** |
| **绘制型** | `绘制` 最大 | 「进入设置页」118.2 / 66.4 / 54.4ms | 首帧画的东西太多：骨架 → 真实内容的替换要就地、分批；别在重建帧上叠大面积绘制 |
| **下发型** | `下发` 最大 | 进仓库详情 64.2ms（下发 52.3） | 命令下发尖峰，通常是新的大图层 / 图片解码，查图层与图片尺寸 |

配套的动效形式清单（哪些形式治哪一类、每帧代价多大）见 [`ui-design.md`](ui-design.md) §3；
页面重建的结构性解法（保活 / 快照）属于动效形式的扩展，落地时要在那份规格里同步。

### 6.1 第一轮改动（落点在此备查，含**试过又退回去的**）

| 改动 | 落点 | 靶子 |
|---|---|---|
| **曲线**：两端速度连续 | 进场 `CubicBezierEasing(0.25, 0, 0.15, 1)`（原 `LinearOutSlowInEasing` 起步速度是平均速度的 **5 倍**）、退场淡化 `LinearEasing`（原 `FastOutLinearInEasing` 末帧还在加速） | **抖动感**（速度突变 = 急动度）；曲线问题是"看着不舒服"的第一嫌疑 |
| **只让一页动** | 旧页从「反向滑出 180ms」改成「**原地**淡出 100ms」；位移 1/4 → **1/10 屏**；进场 300 → **220ms** | 抖动感（两页同时动 + 曲线一进一退 → 相对速度一直在变） |
| **起播门控** | `PageMotion.ENTER_DELAY_MS = 33`（进场延迟 2 帧起播） | 「刚动一下 → 定住 → 猛地跳过去」——把目标页首帧的重活挪到动画开始之前 |
| 同级 / 重页：fade-through | 旧页 110ms 淡净 → 新页延迟 110ms、180ms 淡入（**不重叠**） | 动画型 / 绘制型（同一时刻只有一页在画） |
| 重页过渡降级（台账） | `PageLevel.heavyFirstFrame` + `transitionKindFor()`；台账两页：仓库详情、设置页 | 动画型（244ms）、绘制型（设置页 7 条） |

**试过又退回去的：整页缩放 + 视差**（新页 94%→100%、旧页缩到 96% 且只走 60% 距离）。
本意是做「新页盖上来」的纵深，真机观感**更晃**：全屏内容在位移中缩放会重采样（文字发虚、边缘游移），
两页速度不同又让相对运动更不稳定。**结论：整页位移期间不要叠加缩放**，理由与台账都记在
[`ui-design.md`](ui-design.md) §3。

**关于起播门控的边界**：它只能盖住「一两帧」级别的首帧开销。像仓库详情那种 200ms+ 的首帧，
延迟盖不住 —— 那是页面**首帧瘦身**（骨架先上、内容延后）或数据预取的活，见 §6「动画型 / 等待型」。

「等待」型（消息页 / 个人主页）**这两轮刻意没动**：那不是过渡形式的问题，得先把主线程的活挪走。

## 7. 验收清单（改完照着跑）

- [ ] 出包：`bash tools/build/assemble.sh assemblePerfBeta`（**perfBeta**：release 的性能特征 + beta 签名
      → 能覆盖安装、不掉登录态与缓存；debug 包测出来的不是真实性能，见 `app/build.gradle.kts` 的 buildTypes 注释）；
- [ ] 送包到手机：桥接的 `/app/export` 会把 APK **压成 `.gz`**（手机上装不了），改走容器本机 HTTP ——
      容器与手机共享 loopback（桥接就在 `127.0.0.1:3090`），所以
      `python3 -m http.server 8899 --bind 127.0.0.1`（后台任务）→
      `/app/open?url=http://127.0.0.1:8899/<apk 文件名>` 让手机浏览器下载到 `/sdcard/Download/`；
      用完把服务器停掉；
- [ ] 装机：**由用户在通知栏 / 文件管理器里点安装** —— 设备命令侧的 `pm` **只允许查询**
      （安装 / 卸载 / 清数据都不开放），这一步没有自动通道；
- [ ] 同一台设备、同一刷新率：先 `adb-shell settings get system peak_refresh_rate` 记下来（本机 60）；
- [ ] 同一轮场景（S1–S5，§4 表），每组之间停约 1 秒；
- [ ] `watch` 采一轮 → `analyze --from <起点>` 切窗 → `compare --before 旧.json --after 新.json`；
- [ ] 三个数都要看：**≥100ms 条数必须降**、**超 16ms 比例必须降**、慢帧均值不回升；
- [ ] 别只看总条数：同版本两次会话能差 2 条、最慢能差 42ms（§5）；
- [ ] 结论回写本文档 §5（新版本加一行）与 `VERSION-NOTES.md`。

## 8. 已知局限

| 局限 | 影响 | 想补的话怎么补 |
|---|---|---|
| 只有慢帧明细 + 每分钟比例，**没有 per-scenario 分母** | 说不出「切 Tab 20 次里几次慢」 | 给 `FrameWatch` 加一条：每次导航打点时记「自上次打点以来的帧数」 |
| 「页面」注脚 = 最近一条 UI 日志，不是精确路由 | 极端情况下会归错桶（如动画中途又发生一次导航） | 归因时按「注脚 + 时间」双看，别只看注脚 |
| 阈值写死 60Hz（16ms / 32ms） | 120Hz 设备上系统性低估 | 读数按 `Display.refreshRate` 折算，或把预算做成参数 |
| 日志只留当天 | 跨天对比要当天取走 | 采集完成即取（脚本已落盘到容器） |
| 取数走设备 shell | `adb-shell` 拒绝复合命令 | 脚本已按单命令封装，别在参数里塞管道 |
